# E2E Tests for Every Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Playwright main-path test per frontend route, run locally and by a GitHub Actions workflow against the built frontend, the backend and the shared database (spec: [2026-11-13-e2e-tests-design.md](../specs/2026-11-13-e2e-tests-design.md), issue #127).

**Architecture:** Playwright lives in `apps/frontend` (`playwright.config.ts`, `e2e/`). A `setup` project logs in once through the real form with "Keep me signed in" ticked and saves the browser state; the `chromium` project reuses it. Tests use permanent fixtures (test user, group, seeded book on the user's shelf) and only undo-able actions. `e2e.yml` builds and starts both apps and runs the suite on pushes to `main` and on manual dispatch.

**Tech Stack:** Playwright (`@playwright/test`), Vue 3 + Vite preview, Express backend, Supabase Auth, PostgreSQL (`pg` for the one direct cleanup), GitHub Actions.

---

## Notes for the engineer

- Run every command from `apps/frontend` unless a step says otherwise.
- These are e2e tests of existing pages: there is no feature code to write first. Each task writes a spec, runs it against the real stack, and expects it to **pass**. If it fails, the failure is either a wrong selector (fix the test) or a real bug (stop and report it; do not change app code in this plan).
- `workers: 1`: all tests share one test user, so they run one at a time.
- Never write to rows the test user does not own. Never `TRUNCATE`, `DROP` or reseed.
- Selectors used below were read from the views on 2026-11-13: `LoginView.vue` (`#login-email`, `#login-password`, "Keep me signed in", "Log in"), `CompleteProfileView.vue` (`#profile-name`, `#profile-username`, "Continue"), `CreateGroupView.vue` (`#group-name`, preview `.glance-name`), page titles from `PagePlate` / `PageHeader`.
- How the session is stored: Supabase keeps it under a `localStorage` key matching `sb-<ref>-auth-token` when "Keep me signed in" is ticked (`src/services/auth.ts:45`). The helpers read the access token from there.

```ts
import { expect, type Page } from '@playwright/test';

/** The Supabase access token the app stored for the signed-in user. */
export async function accessToken(page: Page): Promise<string> {
  const token = await page.evaluate(() => {
    for (const store of [localStorage, sessionStorage]) {
      for (let i = 0; i < store.length; i++) {
        const key = store.key(i);
        if (key && /^sb-.+-auth-token$/.test(key)) {
          return (JSON.parse(store.getItem(key) ?? '{}') as { access_token?: string })
            .access_token;
        }
      }
    }
    return undefined;
  });
  if (!token) throw new Error('No Supabase session in the page; is the user signed in?');
  return token;
}

/** Calls DELETE on the API as the signed-in user (teardown only). 404 counts as already gone. */
export async function apiDelete(page: Page, path: string): Promise<void> {
  const response = await page.request.delete(`/api${path}`, {
    headers: { Authorization: `Bearer ${await accessToken(page)}` },
  });
  expect([200, 204, 404], `DELETE ${path} returned ${response.status()}`).toContain(
    response.status(),
  );
}
```

```ts
import { apiDelete } from './api';

test('opening a session starts the timer on the book', async ({ page }) => {
```

```ts
import { expect, test } from '@playwright/test';
import pg from 'pg';
import { profilelessUser, required } from './env';
import { logIn } from './login-form';

test.use({ storageState: { cookies: [], origins: [] } });

/** No API deletes a profile, so the users row is removed directly to keep the account profile-less. */
async function removeProfile(email: string): Promise<void> {
  const client = new pg.Client({ connectionString: required('DATABASE_URL') });
  await client.connect();
  try {
    await client.query('DELETE FROM users WHERE email = $1', [email]);
  } finally {
    await client.end();
  }
}

test('a new account finishes its profile and reaches home', async ({ page }) => {
  const { email, password } = profilelessUser();
  await removeProfile(email); // a previous failed run may have left one
  try {
    await page.goto('/login');
    await logIn(page, email, password);
    await expect(page).toHaveURL(/\/complete-profile$/);

    const username = `e2e${Date.now().toString(36)}`;
    await page.locator('#profile-name').fill('E2E Profileless');
    await page.locator('#profile-username').fill(username);
    await page.getByRole('button', { name: 'Continue' }).click();
    await expect(page).toHaveURL(/\/home$/);
  } finally {
    await removeProfile(email);
  }
});
```

Expected: `2 passed` both times. If the `DELETE` fails with a foreign key error, the profile-less account has other rows (it should not; it only ever finishes its profile) — stop and report.
